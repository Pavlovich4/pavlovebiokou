# 03 — Frontend Architecture (React side)

Every frontend file lives under `resources/js/`. This chapter walks the directories, then the three key config files (`app.tsx`, `vite.config.ts`, `tsconfig.json`) line by line.

## Directory map of `resources/js/`

```
resources/js/
├── app.tsx                 ← ENTRY POINT. Vite loads this first.
├── pages/                  ← Page components. Names match Inertia::render(...) strings.
│   ├── welcome.tsx
│   ├── dashboard.tsx
│   ├── auth/               ← Fortify auth pages (login, forgot-password, …)
│   └── settings/           ← Settings pages (profile, security, appearance)
├── layouts/                ← Layout wrappers. See 05-layout-system.md.
│   ├── app-layout.tsx
│   ├── auth-layout.tsx
│   ├── app/                ← AppSidebarLayout, AppHeaderLayout variants
│   ├── auth/               ← AuthSimpleLayout, AuthCardLayout, AuthSplitLayout
│   └── settings/layout.tsx ← Nested layout for /settings/*
├── components/             ← App-specific reusable pieces (nav, breadcrumbs, forms)
│   └── ui/                 ← shadcn/ui primitives (button, input, dialog, …). Do NOT edit unless intentional.
├── hooks/                  ← Custom React hooks (use-appearance, use-flash-toast, …)
├── lib/                    ← Small utilities. lib/utils.ts has cn() and toUrl().
├── types/                  ← Shared TypeScript types (User, NavItem, AppLayoutProps, …)
├── routes/                 ← GENERATED by Wayfinder. Don't edit. Type-safe route callers.
├── actions/                ← GENERATED by Wayfinder. Don't edit. Type-safe controller callers.
└── wayfinder/index.ts      ← Wayfinder runtime helpers used by generated code.
```

Rules of thumb:

- **Anything under `routes/`, `actions/`, or `wayfinder/` is generated.** Don't touch. They're excluded from linting/formatting on purpose (`vite.config.ts:49-52`).
- **`components/ui/*` is shadcn-owned.** These files were dropped in by the shadcn CLI; if you need to tweak one, do so deliberately (they're excluded from formatting to preserve the shadcn structure — `vite.config.ts:69`).
- **Pages are chosen by name, not by URL.** A controller writes `Inertia::render('settings/profile', …)`, Inertia looks up `resources/js/pages/settings/profile.tsx`. The URL is separate — decided by the route file.

## The entry point: `resources/js/app.tsx`

Here it is in full, then a line-by-line walk.

```tsx
// resources/js/app.tsx
import { createInertiaApp } from '@inertiajs/react';
import { Toaster } from '@/components/ui/sonner';
import { TooltipProvider } from '@/components/ui/tooltip';
import { initializeTheme } from '@/hooks/use-appearance';
import AppLayout from '@/layouts/app-layout';
import AuthLayout from '@/layouts/auth-layout';
import SettingsLayout from '@/layouts/settings/layout';

const appName = import.meta.env.VITE_APP_NAME || 'Laravel';

void createInertiaApp({
    title: (title) => (title ? `${title} - ${appName}` : appName),
    layout: (name) => {
        switch (true) {
            case name === 'welcome':
                return null;
            case name.startsWith('auth/'):
                return AuthLayout;
            case name.startsWith('settings/'):
                return [AppLayout, SettingsLayout];
            default:
                return AppLayout;
        }
    },
    strictMode: true,
    withApp(app) {
        return (
            <TooltipProvider delayDuration={0}>
                {app}
                <Toaster />
            </TooltipProvider>
        );
    },
    progress: {
        color: '#4B5563',
    },
});

initializeTheme();
```

Now the walkthrough:

- **Lines 1–7 — imports.** The `@/` prefix is a TypeScript path alias (`@/components/...` → `resources/js/components/...`). Defined in `tsconfig.json:111`. Imports for `Toaster`, `TooltipProvider`, and `initializeTheme` are all things we want to run at the *root* of the app so every page benefits.

- **Line 9 — app name.** `import.meta.env.VITE_APP_NAME` reads the value of `VITE_APP_NAME` from `.env` at build time. Only env vars prefixed with `VITE_` are exposed to the client. Falls back to `'Laravel'`.

- **Line 11 — `void createInertiaApp({...})`.** `createInertiaApp` mounts the whole Inertia + React tree into `#app`. `void` is a JS trick that says "I don't care about the promise it returns; don't complain about the unhandled result".

- **Line 12 — `title:`.** A function that takes the per-page title (set by `<Head title="Dashboard" />`) and returns the final `<title>` tag value. Here: `"Dashboard - Laravel"`. If a page provides no title, you just get `"Laravel"`.

- **Lines 13–24 — `layout:` (this is the layout resolver).** Takes the page name Inertia is about to render and returns the layout(s) to wrap it in. The `switch (true) { case … }` pattern is a JS idiom for evaluating boolean cases; the first `case` whose expression is truthy wins. Order:
  - `welcome` → no layout (the welcome page renders its own full-page markup).
  - Anything under `auth/` → wrapped in `AuthLayout` (login, forgot-password, confirm-password, …).
  - Anything under `settings/` → wrapped in `AppLayout` *then* `SettingsLayout` (outer to inner). Array = nested layouts.
  - Everything else → `AppLayout`.

  Full details of how this ties into `Page.layout` are in [05-layout-system.md](05-layout-system.md).

- **Line 25 — `strictMode: true`.** Wraps the app in React's `<StrictMode>`. In development, React deliberately double-invokes some functions to catch side-effect bugs; in production this is a no-op.

- **Lines 26–33 — `withApp(app) { … }`.** Gives you the mounted app element and lets you wrap it in providers. Here:
  - `TooltipProvider` (from Radix) provides context so any `<Tooltip>` component anywhere in the tree just works. `delayDuration={0}` makes tooltips appear instantly.
  - `Toaster` renders the container that Sonner uses to display toast notifications.

  Anything you want to be *globally available* (theme provider, query client, i18n) goes here.

- **Lines 34–36 — `progress: { color }`.** Inertia's built-in progress bar (the thin colored bar that appears at the top of the browser during navigation). Only the color is customized.

- **Line 40 — `initializeTheme()`.** Runs the theme setup from `use-appearance.tsx` immediately on load: reads the stored preference, applies the `dark` class to `<html>` if needed, and starts listening for the OS-level `prefers-color-scheme` change. Called *outside* `createInertiaApp` because it has to run before the first render to avoid a flash of the wrong theme.

## The bundler: `vite.config.ts`

```ts
// vite.config.ts
import inertia from '@inertiajs/vite';
import { wayfinder } from '@laravel/vite-plugin-wayfinder';
import babel from '@rolldown/plugin-babel';
import tailwindcss from '@tailwindcss/vite';
import react, { reactCompilerPreset } from '@vitejs/plugin-react';
import laravel from 'laravel-vite-plugin';
import { bunny } from 'laravel-vite-plugin/fonts';
import { defineConfig, lazyPlugins } from 'vite-plus';

export default defineConfig({
    plugins: lazyPlugins(() => [
        laravel({
            input: ['resources/css/app.css', 'resources/js/app.tsx'],
            refresh: true,
            fonts: [
                bunny('Instrument Sans', {
                    weights: [400, 500, 600],
                }),
            ],
        }),
        inertia(),
        react(),
        babel({
            presets: [reactCompilerPreset()],
        }),
        tailwindcss(),
        wayfinder({
            formVariants: true,
        }),
    ]),
    // … (server watch config and lint/fmt options)
});
```

Plugin by plugin:

- **`laravel(...)`** — the Laravel Vite plugin. Tells Vite what the entry points are so Blade can pick them up with `@vite(['resources/css/app.css', 'resources/js/app.tsx'])`. `refresh: true` triggers a browser reload when PHP files change during dev. `fonts: [bunny('Instrument Sans', ...)]` bundles the Bunny Fonts CSS for Instrument Sans automatically.
- **`inertia()`** — the Inertia Vite plugin. Handles SSR bundling (there's a separate `resources/js/ssr.tsx` in some setups) and dev-mode niceties.
- **`react()`** — enables JSX/TSX compilation via `@vitejs/plugin-react`.
- **`babel({ presets: [reactCompilerPreset()] })`** — runs the React Compiler on your components. This is the new (React 19) optimizer that auto-memoizes components. You get free performance without wrapping everything in `useMemo` / `useCallback`.
- **`tailwindcss()`** — the Tailwind v4 plugin. Tailwind v4 doesn't need a `tailwind.config.js`; configuration lives inside `resources/css/app.css` via `@theme` directives.
- **`wayfinder({ formVariants: true })`** — reads Laravel routes and controllers, emits typed TS files under `resources/js/routes/**` and `resources/js/actions/**`. `formVariants: true` gives you the `.form()` helper that `<Form {...route.form()} />` uses.
- **`lazyPlugins(() => [...])`** — a `vite-plus` helper that defers plugin instantiation until Vite actually starts them, avoiding cold-start work.

Other blocks:

- **`server.watch.ignored`** — tells Vite's file watcher to ignore agent/tooling folders (`.claude`, `.cursor`, `vendor`, etc.) so they don't trigger reloads.
- **`lint.ignorePatterns`** — the linter skips generated Wayfinder files and shadcn-owned files. Edit these only intentionally.
- **`fmt`** — code formatting config (4-space indent, single quotes, semicolons, sort Tailwind classes with `cn`/`clsx`/`cva`). Runs via `npm run check` / `npm run check:fix`.

## TypeScript: `tsconfig.json` (the parts that matter)

Full file has TS's whole option catalog commented out. The active settings:

```json
{
  "compilerOptions": {
    "target": "ESNext",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "allowJs": true,
    "noEmit": true,
    "isolatedModules": true,
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "strict": true,
    "noImplicitAny": true,
    "skipLibCheck": true,
    "paths": {
      "@/*": ["./resources/js/*"]
    },
    "jsx": "react-jsx"
  },
  "include": [
    "resources/js/**/*.ts",
    "resources/js/**/*.d.ts",
    "resources/js/**/*.tsx"
  ]
}
```

The important ones:

- **`"paths": { "@/*": ["./resources/js/*"] }`** — the `@/` alias you see in every import. `@/components/ui/button` resolves to `resources/js/components/ui/button`. Without this, imports would look like `../../../components/ui/button`. The Vite side automatically picks up this alias.
- **`"strict": true`** + **`"noImplicitAny": true`** — TypeScript's strictest mode. Every variable, param, and return type is checked. If you write `function foo(x) { … }` without a type on `x`, TypeScript will error.
- **`"noEmit": true`** — TypeScript never writes `.js` output; Vite handles compilation. `tsc` is only used for type checking (`npm run types:check` runs `tsc --noEmit`).
- **`"jsx": "react-jsx"`** — the modern JSX transform. You don't need `import React from 'react'` at the top of every file.
- **`"skipLibCheck": true`** — don't type-check `.d.ts` files inside `node_modules`. Faster and prevents third-party type conflicts from blocking you.

## Pages: name → file

The Inertia server side does:

```php
Inertia::render('settings/profile', [...]);
```

The Inertia client does *approximately*:

```ts
import(`./pages/${'settings/profile'}.tsx`).then(module => mount(module.default));
```

So the page name is a slash-separated path relative to `resources/js/pages/` with `.tsx` implied. That's why `pages/settings/profile.tsx` is called `'settings/profile'`, and `pages/auth/confirm-password.tsx` is called `'auth/confirm-password'`.

Filename → URL is *not* automatic. The URL is whatever the route file says. You could rename `pages/settings/profile.tsx` to `pages/foo.tsx` and change `Inertia::render('foo', …)` — the URL `/settings/profile` would still work.
