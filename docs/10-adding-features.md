# 10 — Adding Features (Practical Recipes)

Short, actionable recipes for the most common changes you'll make. Each assumes you've read [01-overview.md](01-overview.md).

## Add a new public page

**Goal**: create a `/about` page.

1. Create the page component:

   ```tsx
   // resources/js/pages/about.tsx
   import { Head } from '@inertiajs/react';

   export default function About() {
       return (
           <>
               <Head title="About" />
               <div className="p-8">
                   <h1 className="text-2xl font-bold">About us</h1>
                   <p className="mt-4">Hello!</p>
               </div>
           </>
       );
   }

   About.layout = { breadcrumbs: [{ title: 'About', href: '/about' }] };
   ```

2. Register the route:

   ```php
   // routes/web.php
   Route::inertia('about', 'about')->name('about');
   ```

3. Restart `composer run dev` (or wait for the Vite/Wayfinder watchers). Visit `/about`.

The layout resolver's default case wraps you in `AppLayout` (which requires login). If you want the page to be truly public with no shell, set `About.layout = null;` at the bottom.

## Add a new authenticated page (with sidebar)

Same as public page but the route uses auth middleware:

```php
Route::middleware(['auth', 'verified'])->group(function () {
    Route::inertia('reports', 'reports')->name('reports');
});
```

Add a nav item so users can find it. Open `resources/js/components/app-sidebar.tsx` (or wherever main-nav items are defined) and add:

```tsx
{ title: 'Reports', href: '/reports', icon: FileText },
```

Icon comes from `lucide-react`.

## Add a new settings page

Settings pages get two layouts (`AppLayout` + `SettingsLayout`) automatically thanks to the resolver.

1. Route (in `routes/settings.php`, inside the `['auth', 'verified']` group):

   ```php
   Route::inertia('settings/notifications', 'settings/notifications')->name('notifications.edit');
   ```

2. Page:

   ```tsx
   // resources/js/pages/settings/notifications.tsx
   import { Head } from '@inertiajs/react';

   export default function Notifications() {
       return (
           <>
               <Head title="Notifications" />
               <h2 className="text-lg font-medium">Notifications</h2>
           </>
       );
   }
   ```

3. Add a link in the sub-nav (`resources/js/layouts/settings/layout.tsx`):

   ```tsx
   import { edit as editNotifications } from '@/routes/notifications'; // add

   const sidebarNavItems: NavItem[] = [
       // …
       { title: 'Notifications', href: editNotifications(), icon: null },
   ];
   ```

   The `@/routes/notifications` file is generated by Wayfinder as soon as the PHP route exists.

## Add a form that POSTs to a controller

**Goal**: a "Send feedback" form.

1. Controller + route:

   ```php
   // routes/web.php (inside auth group if needed)
   Route::post('feedback', [FeedbackController::class, 'store'])->name('feedback.store');
   ```

   ```php
   // app/Http/Controllers/FeedbackController.php
   public function store(Request $request)
   {
       $data = $request->validate(['message' => 'required|string|max:1000']);
       // …save, email, etc.
       Inertia::flash('toast', ['type' => 'success', 'message' => 'Thanks for the feedback!']);
       return back();
   }
   ```

2. Restart dev so Wayfinder emits `resources/js/routes/feedback/index.ts` (or `resources/js/actions/App/Http/Controllers/FeedbackController.ts`).

3. Frontend form:

   ```tsx
   import { Form } from '@inertiajs/react';
   import { Button } from '@/components/ui/button';
   import { Label } from '@/components/ui/label';
   import { store } from '@/routes/feedback';
   import InputError from '@/components/input-error';

   export function FeedbackForm() {
       return (
           <Form {...store.form()} resetOnSuccess={['message']}>
               {({ processing, errors }) => (
                   <>
                       <Label htmlFor="message">Message</Label>
                       <textarea id="message" name="message" required />
                       <InputError message={errors.message} />
                       <Button disabled={processing}>Send</Button>
                   </>
               )}
           </Form>
       );
   }
   ```

`errors.message` populates automatically if validation fails; the success toast is shown by `use-flash-toast`.

## Add a new shared prop (available everywhere)

**Goal**: expose `flags` (feature flags) to every page.

1. In `HandleInertiaRequests::share()`:

   ```php
   // app/Http/Middleware/HandleInertiaRequests.php
   return [
       ...parent::share($request),
       'name' => config('app.name'),
       'auth' => ['user' => $request->user()],
       'sidebarOpen' => ! $request->hasCookie('sidebar_state') || $request->cookie('sidebar_state') === 'true',
       'flags' => config('feature_flags'),
   ];
   ```

2. Consume anywhere:

   ```tsx
   import { usePage } from '@inertiajs/react';

   const { flags } = usePage().props as { flags: { newDashboard: boolean } };
   if (flags.newDashboard) { … }
   ```

3. (Optional) Add a type to `resources/js/types/` and cast `usePage<AppSharedProps>()` for autocomplete.

## Add a new layout variant

Full walkthrough in [05-layout-system.md](05-layout-system.md#recipes). Short form:

1. Create the layout file under `resources/js/layouts/`.
2. Add a case in `app.tsx`'s resolver.
3. Optional: pass per-page props with `Page.layout = { … }` matching the layout's prop types.

## Trigger a toast from the backend

Server:

```php
Inertia::flash('toast', ['type' => 'success', 'message' => 'Saved!']);
return back();
```

Client: nothing — `use-flash-toast` (called once in a layout) picks it up and calls Sonner.

`type` must be one of `'success' | 'info' | 'warning' | 'error'` (see `resources/js/types/ui.ts:11-14`).

## Regenerate Wayfinder types manually

Usually automatic. If you need to force it:

- Restart the dev server: `composer run dev` (which runs `php artisan dev`), or `npm run dev` alone.
- If TypeScript still shows stale errors, restart the TS server in your editor.

## Run tests

Everything:

```bash
php artisan test --compact
```

Narrow to a file:

```bash
php artisan test tests/Feature/Auth/ConfirmablePasswordTest.php
```

Filter by name:

```bash
php artisan test --filter='confirms password'
```

## Format & lint

PHP:

```bash
vendor/bin/pint --dirty --format agent
```

TypeScript / CSS:

```bash
npm run check          # report issues
npm run check:fix      # auto-fix
npm run types:check    # tsc --noEmit
```

## Common file-naming conventions

- **Pages** (`resources/js/pages/…`): kebab-case filename matches the Inertia name. `two-factor-challenge.tsx` → `Inertia::render('auth/two-factor-challenge')`.
- **Components**: kebab-case filename, default-exported PascalCase component.
- **Hooks**: `use-something.ts[x]`, function `useSomething`.
- **Routes / actions**: never edit; leave to Wayfinder.
