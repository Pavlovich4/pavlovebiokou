# 11 — Dev Workflow & Gotchas

Commands you'll run daily, and the traps that eat the most time when you're new to the stack.

## Starting the dev environment

The recommended way — one command that spins up PHP server + queue + logs + Vite in parallel:

```bash
composer run dev
```

Under the hood this executes `php artisan dev`, which in turn runs multiple processes (via `concurrently`). One terminal, four services.

If you'd rather run pieces separately:

```bash
# Terminal 1 — Laravel
php artisan serve

# Terminal 2 — Vite (hot-reloading JS/CSS + Wayfinder regen)
npm run dev

# Terminal 3 — logs (optional)
php artisan pail
```

## Production build

```bash
npm run build
```

Compiles JS/CSS into `public/build/`. Laravel's `@vite(...)` Blade directive reads `public/build/manifest.json` to know which chunks to load.

With SSR:

```bash
npm run build:ssr
```

Produces both a client bundle and a server bundle at `bootstrap/ssr/ssr.mjs`. To actually serve SSR, you'd run that Node script alongside PHP (see `config/inertia.php:'ssr' => ['enabled' => true, 'url' => 'http://127.0.0.1:13714']`).

## Tests

Full suite:

```bash
php artisan test --compact
```

One file:

```bash
php artisan test tests/Feature/ExampleTest.php
```

Filter by name:

```bash
php artisan test --filter=UserCanConfirmPassword
```

Pest directly (same options apply):

```bash
vendor/bin/pest --filter=UserCanConfirmPassword
```

Composer's `test` script runs formatting + PHPStan + tests all together:

```bash
composer test
```

## Formatting & linting

PHP with Pint:

```bash
vendor/bin/pint --dirty --format agent   # only files you changed
vendor/bin/pint --format agent           # everything
```

Do NOT use `vendor/bin/pint --test --format agent` — that's a dry run that won't fix anything.

TypeScript / CSS / JSON:

```bash
npm run check        # lint + format check
npm run check:fix    # auto-fix
npm run types:check  # tsc --noEmit
```

PHPStan (static analysis):

```bash
composer types:check
```

## The Vite manifest error

**Symptom**:
```
Illuminate\Foundation\ViteException: Unable to locate file in Vite manifest: resources/js/app.tsx
```

**Cause**: Blade is trying to load Vite assets but no build exists and no dev server is running.

**Fix**: either
- Start the dev server: `npm run dev` (or `composer run dev`), OR
- Build once: `npm run build`.

## Common gotchas

### 1. Editing generated files

Files under `resources/js/routes/**`, `resources/js/actions/**`, and `resources/js/wayfinder/**` are regenerated by the Wayfinder Vite plugin. Any edits will be lost on the next run. Also excluded from linting/formatting (`vite.config.ts:49-52`).

If you need a different URL or method, change the Laravel route, not the TS file.

### 2. Editing `components/ui/*` without care

Those files were dropped in by the shadcn CLI. They're intentionally excluded from formatting to preserve shadcn's structure. You *can* edit them — just be aware that re-running `npx shadcn add button` will overwrite your changes.

### 3. Forgetting the `@/` alias

If your import looks like `../../components/foo`, you're missing the alias. Use `@/components/foo` — cleaner, and TypeScript/Vite both understand it (config at `tsconfig.json:110-112`).

### 4. `Page.layout` key typos

`Login.layout = { titel: 'Log in' }` (typo) will pass TypeScript because `.layout` is loosely typed. The layout will just render empty strings. Double-check the object keys match the layout's expected props (`title`, `description`, `breadcrumbs`, …).

### 5. Adding a route but Wayfinder doesn't emit for it

Restart the Vite dev server. The plugin watches PHP files but sometimes misses changes to controllers or route options. `Ctrl+C` and `npm run dev` again.

### 6. Cookies aren't reaching the server

If you're reading a cookie in a middleware (like `sidebar_state` in `HandleInertiaRequests`), it must be listed in `bootstrap/app.php:18`'s `encryptCookies(except: [...])` — otherwise Laravel will fail to decrypt the value the JS side wrote.

### 7. Login/logout not working after Fortify config change

`config/fortify.php` is cached in production. After changing features (adding registration, etc.), run:

```bash
php artisan config:clear
```

### 8. Dark mode flashing on load

If you see a brief flash of the wrong theme, make sure `initializeTheme()` is called *outside* React (last line of `resources/js/app.tsx`). Wrapping it in a `useEffect` would run it *after* React's first paint, causing the flash.

### 9. Two-factor confirmation loops

If clicking the security page bounces you between confirm-password and the security page forever, check that `Fortify::confirmPasswordView(...)` in `FortifyServiceProvider` renders a page whose form actually POSTs to `store.form()` from `@/routes/password/confirm`. That's what tells the server the password was confirmed.

## Environment variables

- `.env` is git-ignored; `.env.example` is the template.
- Client-side reads only `VITE_*` variables via `import.meta.env` (see `resources/js/app.tsx:9`).
- Server-side reads any via Laravel's `config()`/`env()` helpers.

Reload dev server after editing `.env` — Vite doesn't hot-reload env changes.

## CI check

Runs everything the CI would:

```bash
composer ci:check
```

That's `npm run check` + `npm run types:check` + `composer test`.

## Where to look when something breaks

| Symptom | First place to look |
|---------|---------------------|
| Blank white page | Browser devtools console; `HandleInertiaRequests` returning bad JSON |
| 419 CSRF error | Session expired; refresh the page |
| 422 validation but no errors on the form | Field `name` attribute doesn't match the validation rule key |
| "Component not found" | Page name in `Inertia::render(...)` doesn't match a file in `resources/js/pages/` |
| Sidebar doesn't remember state | `sidebar_state` cookie not being written (check `bootstrap/app.php:18` excepts it from encryption) |
| Tailwind class not applying | Class may be dynamic — Tailwind can't detect string concatenation. Use full class names or extract to a variable Tailwind can see. |
| Theme flash on load | `initializeTheme()` moved inside React, or `resources/css/app.css` missing dark-mode config |
